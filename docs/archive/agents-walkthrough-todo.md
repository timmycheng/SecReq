# 走查发现问题

1. 用户体系
   1. 增加登录界面
   2. 右侧增加链接，像dashboard系统一样
   3. 用户角色分成开发和安全，不用审计和风管角色
2. 问卷功能
   1. 新建项目
      1. 新建项目弹窗取消，直接跳到step1
   2. step-1
      1. 项目编码自动生成
      2. 项目类型可多选，一个项目（系统）可能包含多种形式
      3. 部署环境去掉，所属业务条目去掉
      4. 合规目标用radio框多选，等保三级应该就只是等级保护
      5. 基本信息和定级合并，相关信息直接在基本信息里输入就好
      6. 增加是否与外部系统连接的选项，应该是个列表
   3. step-2
      1. 与step-1合并
   4. step-3
      1. 改成通过业务需求书输入自动生成，新增功能点开有个黏贴段落的组件，用户把需求的内容贴上来，自动生成需要的功能需求点，用户确认后增加到列表里
   5. step-4
      1. 明确一下数据资产是什么意思，我都不太懂
      2. 这块就是想做成，开发的把数据字典贴上来或者传上来，自动识别数据分级，生成安全需求
   6. step-5
      1. 角色要数量是不是有点没有必要
      2. 资源是否跟功能清单对应
   7. step-6
      1. 跟step-2合并，定级之后直接就出这些要求的，可以和step-1一起展示
   8. step-7
      1. 常用组件根据层级分分类，然后现在的组件也不太美观
      2. 许可证是否可以根据软件名称自动生成，同时要识别许可证的风险
   9. step-8
      1. API接口和基础设施分开
      2. 基础设施清单要详细一点，分为服务器、网络，设计阶段不会给具体的网络地址，相当于预留；服务器要列规格：CPU核数、内存、操作系统、硬盘
3. 生成产物
    1. 界面调整一下，好看一点
    2. 不用生成这些个word了，因为跟我们的模板也不一样，可以先以WEB形式展示，提供一个黏贴到word的按钮
    3. 安全需求清单的展示要更清楚一点，需求内容里的小字目前被截断了，可以分多行展示
    4. 需求不要再折叠了，把折叠的内容平铺展示，设计一下格式
    5. 需求不用指定责任人，就一个确认动作就好，然后列表上包含批量操作
    6. 需求里的来源，为啥会有类似data_asset#3这种样式，改成中文，清楚一点
4. 门禁
    1. 暂时去掉，对于权限的管理，就只是开发的人只能看到自己新建的项目，安全可以看到所有，就好了
5. 系统管理
    1. 知识库的策略可视化，可配置
    2. 这个系统本身也是存储敏感数据的，相关基础安全功能也要到位
6. 其他
   1. 标题去掉（需求+设计阶段），就叫安全需求管理平台好了
