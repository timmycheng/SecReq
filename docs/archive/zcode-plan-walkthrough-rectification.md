## 阶段一：用户体系、权限与布局框架（TODO 1 / 4 / 6.1）

1. **登录与真实认证**
   - `PlatformUser` 加 `password_hash`（stdlib pbkdf2_hmac，不加新依赖）；新增 sessions 表
   - `POST /api/auth/login` 校验账密签发 token；`auth_guard` 改 Bearer token；新增改密接口
   - 前端新增 `LoginPage.tsx`（#/login，未登录强制跳转）；移除自动 pm_wang 登录；顶栏右侧改「用户名+退出」
   - 种子账号发默认密码（首次登录可改）
2. **角色简化为 开发/安全**
   - `PLATFORM_ROLES` 精简为 `developer(开发)/security(安全)`；种子用户调整（dev_li、pm_wang→developer；sec_chen、sec_zhao→security；风管/审计账号移除）
   - 各 router `require_write_roles` 参数同步；前端 `ROLE_COLOR`、权限点清理；存量库角色迁移脚本
3. **数据权限（替代门禁）**
   - `Project` 加 `owner_user_id` 列（lifespan 自动迁移，存量项目归入种子开发账号）
   - 创建项目时写入 owner；列表/详情/写接口按角色过滤：开发只见/只改自己创建的，安全可见可操作全部
4. **下线门禁**
   - 删除前端 `#/review` 路由与 `ReviewPage.tsx`；后端 `routers/review.py`、`gate_service.py` 从应用中摘除（表保留不动）；项目状态机简化
5. **布局与品牌**
   - 改为 AntD Layout+左侧菜单（dashboard 风格：项目列表/系统管理），顶栏右侧用户区；标题改为「安全需求管理平台」（index.html、App、README）

**验收**：无密码不能进系统；开发登录只看到自己的项目；无任何门禁入口；侧边导航可用。

## 阶段二：向导重构（TODO 2.1 / 2.2 / 2.3 / 2.6 / 2.7 / 2.8 / 2.9）

新向导仍为 8 步：**项目信息与定级 → 功能清单 → 数据字典 → 权限矩阵 → 组件与许可证 → API 接口 → 基础设施 → 确认生成**

1. **新建项目直通 Step1**：去掉新建弹窗，首页按钮直接 `POST /api/projects`（项目编码自动生成，如 `XM2026-0001`）并跳转向导
2. **新 Step1「项目信息与定级」**（合并原 Step1+2+6）
   - 项目类型改多选；去掉部署环境、所属业务条目；合规目标改卡片式多选，「等保三级」改叫「等级保护」
   - 定级区：5 题问卷内联（可折叠），也可直接手选等级；保留自动建议等级+判定理由（`services/grading.py` 不动）
   - 定级后即时展示：按等级推导的密码/会话策略基线（原 Step6 内容，可展开覆盖，`AuthConfig` 保留）与主要合规要求
   - 新增「外部系统连接」列表：名称/用途/数据方向（接入/流出/双向）/是否含敏感数据；新模型+API，规则引擎加 external_system 触发器（KB 补 1~2 条模板）
3. **原 Step2 删除**（GradingSurvey 数据结构保留，并入 Step1 读写）
4. **Step5 权限矩阵精简**：去掉「角色数量」；新增「从功能清单导入资源」按钮（按功能生成候选资源）
5. **Step7 组件与许可证**
   - 常用组件按层级分组展示（点选添加的 chips 网格，替代 datalist），美化录入弹窗
   - 内置「组件→默认许可证」映射：选组件自动填许可证；新增许可证风险库（宽松/中等/copyleft 高风险）并标风险 tag；高风险许可证触发新需求（KB 加 license 触发模板）
6. **Step8 拆分为两步**
   - API 接口：原表保留
   - 基础设施：分服务器/网络（+数据库/中间件）；服务器含 CPU 核数/内存/操作系统/磁盘；网络设备地址设计期预留（IP 可空）
7. `WizardPage` STEPS、`ConfirmStep` 汇总、`step_store.py` 同步重排

## 阶段三：智能录入（TODO 2.4 / 2.5）

1. **Step3 功能清单「粘贴生成」**
   - 弹窗粘贴业务需求文本 → 调 LLM（OpenAI 兼容接口，地址+Key 在系统设置配置）→ 返回候选功能点（名称/模块/分类/是否涉交易/是否互联网暴露建议）→ 用户勾选确认入列
   - 未配置 LLM 时降级规则版（分类关键词切句）
   - 后端 `POST /api/projects/{id}/features/extract`
2. **Step4 数据字典「粘贴/上传+自动分级」**
   - 支持粘贴 TSV/表格文本或上传 CSV/XLSX → 解析出表/字段
   - 自动分级：敏感字段模式库（扩展 `MASK_FIELD_PATTERNS`，对齐 JR/T 0197 附录A 典型数据）推断字段级/PII/敏感PII；表级=字段最高级，资产级=表最高级
   - 确认界面逐条可修正后入库；安全需求复用现有 data_asset 触发器生成
   - 后端解析接口（只返回建议不入库）+ 确认后走现有保存接口

## 阶段四：生成产物重构（TODO 3）

1. **产物页 Web 化**：按章节 Web 视图展示（定级建议/安全需求/安全设计/SBOM 与漏洞）；每章节+全文「复制到 Word」按钮（HTML 剪贴板写入，保留标题层级/表格/标红格式，粘进 Word 即排版）

   - 取消行折叠，平铺展示：描述全文多行、验收标准、合规依据、触发原因全部直接可见

4. 产物页整体排版美化
